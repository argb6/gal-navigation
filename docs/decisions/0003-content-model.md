# ADR-0003: 内容数据模型设计

## 状态

已采纳

## 日期

2026-06

## 背景

需要存储站点导航数据。数据特点：

- 站点数量：100-500 条
- 查询模式：全量读取（主站列表）、单条读取（详情页）、按分类过滤
- 写入频率：低（人工维护）
- 无复杂关系：站点之间无外键关联

## 决策

使用 Cloudflare D1（SQLite），简单扁平表结构。

## 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| `item_key` | TEXT PK | 站点唯一标识 |
| `title` | TEXT | 站点名称 |
| `category` | TEXT | 分类（5 种） |
| `tags` | TEXT | 逗号分隔标签 |
| `short_desc` | TEXT | 简短描述 |
| `url` | TEXT | 站点链接 |
| `icon_path` | TEXT | 图标路径 |
| `md_content` | TEXT | 详情页富文本 |
| `updated_at` | TEXT | 更新时间 |

## 原因

1. **简单直接**：100-500 条数据不需要复杂的关系型设计
2. **全量读取为主**：主站一次加载所有数据，客户端过滤
3. **item_key 作主键**：人类可读，前端可直接用作标识

## 影响

- Worker 查询全量数据，客户端 JS 负责过滤和搜索
- tags 字段用逗号分隔，非规范化存储
- category 值需要维护映射表

## 替代方案

| 方案 | 否决原因 |
|------|----------|
| KV 存储全部数据 | D1 支持 SQL 查询 |
| 关联表（categories / tags） | 数据量小，过度设计 |
| 外部数据库 | 增加延迟和运维复杂度 |
