# ADR-0007: 缓存策略设计

## 状态

已采纳

## 日期

2026-06

## 背景

除了结构化数据外，还有几类非结构化数据需要存储：轮播图列表、推荐项列表、捐款名单、状态监控数据、站点公告。

数据特点：读多写少、无需 SQL 查询、值为 JSON 或纯文本。

## 决策

使用 Cloudflare KV，按用途分为多个命名空间。

## 数据分类

| 类型 | 格式 | 更新频率 |
|------|------|----------|
| 轮播图 | JSON 数组 | 低 |
| 推荐项 | JSON 数组 | 低 |
| 捐款名单 | JSON 数组 | 低 |
| 监控状态 | JSON 对象 | 高（每次检测） |
| API 缓存 | JSON 对象 | 中（每天 3 次） |
| 公告 | 纯文本 | 低 |

## 原因

1. **KV 适合键值场景**：都是「一个 key 对应一个 JSON 值」
2. **全球边缘复制**：KV 读取在边缘节点，延迟极低
3. **无需 SQL**：不需要 WHERE/JOIN 等查询
4. **独立命名空间**：按用途隔离，权限清晰

## 读取容错

```js
try {
  return JSON.parse(raw);
} catch (e) {
  return raw.split(",").map(s => s.trim()).filter(Boolean);
}
```

## 影响

- KV 有最终一致性（写入后最多 60 秒生效）
- 命名空间需要在部署配置中绑定

## 替代方案

| 方案 | 否决原因 |
|------|----------|
| 全部存 D1 | KV 更适合简单键值 |
| 外部 Redis | 增加延迟和运维复杂度 |
| 硬编码到 Worker | 需要重新部署才能更新 |
