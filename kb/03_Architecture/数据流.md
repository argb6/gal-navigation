# 数据流

> [!abstract] Summary
> 现网页面只有两条路径：Worker 拼好 HTML（B-SSR），或把 JSON 注入脚本再在浏览器画（B-JSON）。图片走 R2，不走这两条。

旧笔记里的 B-REST（`d1-rest.js` 管理 CRUD）不在本仓 `worker/` 页面列表里。不要再当成现网通路。

## Definition

| 路径 | 谁渲染 | 现网页 |
|------|--------|--------|
| B-SSR | Worker 查库后输出 HTML | detail、friend、palace、donate 名单、status 主体、about/help/index 静态壳 |
| B-JSON | Worker 注入全局变量，浏览器拼卡片/轮播 | websearch：`NAV_DATA` / `HERO_IMAGES` / `FEATURED_KEYS` |

```
D1 / KV
  → Worker fetch
  → HTML（CSS/JS 内联；B-JSON 再带 safeJson 注入）
  → 浏览器按 gd- class 画
```

静态图：浏览器直接请求 `assets.galnavi.top`，见 [[存储]] 的 R2 一节。

`robots.txt` / `sitemap.xml` 由 **index** 内联字符串返回（对照 `worker/share/`）。sitemap 含 `/`、`/nav/`、detail/about/help/palace/donate/friend、`/status/`。error 运行时向 index 拉 sitemap 做转发白名单。

主站 / 详情读 Cookie `gd-nsfw`（1 正常 / 2 显示 NSFW），`Set-Cookie` 每次刷新 24h。对照 `worker/shared/security.js`。

## B-JSON（websearch）

与 GitHub `worker/layer/database/d1.js`、`kv.js` 同一套名字：

1. `env.DB` 查 `navi_sites`（`is_active IN (1, 2)`）
2. `env.HERO_KV.get("hero_images")`、`env.FEATURED_KV.get("featured_items")`
3. `safeJson()` 后写入 `var NAV_DATA = …` 等
4. 客户端读全局变量画卡片和轮播

解析 KV 失败时：JSON 不成再按逗号拆，再不成给空数组。layer 里的 `fetchHeroImages` 就是这段对照实现。

## 各页读什么

| 页面 | D1 | KV |
|------|----|----|
| 主站 | `navi_sites` | `hero_images`、`featured_items` |
| 详情 | `navi_sites` 按 `item_key` | — |
| 殿堂 | `env.group1` 的 `resources` | — |
| 友链 | D1 库 `friend` 的 `sites`（读 + POST 插入） | — |
| 捐献 | — | `donors` |
| 状态 | 代码里**可以**查 `navi_sites`；现网 `status.toml` **没有** D1，走页内兜底清单 | `state`、`api_cache`、`notice` |
| 关于 / 帮助 / 首页 | 现网 toml 无库 | — |
| 404 | 无库；sitemap 经 index binding | — |
