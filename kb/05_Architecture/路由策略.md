# 路由策略

## Summary

error.js 作为 catch-all 路由器，通过 Cloudflare Service Binding 将请求分发到各页面 Worker，未命中白名单返回 404。

## Definition

| 路由 | 目标 Worker |
|------|------------|
| `/` | index |
| `/nav/` | websearch |
| `/nav/detail/` | detail |
| `/nav/about/` | about |
| `/nav/help/` | help |
| `/nav/palace/` | palace |
| `/nav/donate/` | donate |
| `/nav/friend/` | friend |
| `/nav/api/*` | websearch |
| `*`（其他） | 404 内联页 |

## Architecture

```
请求 → error.js
  ├─ loadRoutes(): 读 sitemap.xml 合并 DEFAULT_ROUTES（5 分钟缓存）
  ├─ resolveService(path): 查路由表
  ├─ 命中 → env[service].fetch(request)（service binding 转发）
  └─ 未命中 → render404(path)（内联 HTML 错误页）
```

## Implementation

- 静态路由表 `DEFAULT_ROUTES` 硬编码在 error.js
- 动态路由：从 `index` service binding 抓取 `sitemap.xml`，解析 `<loc>` 标签
- 404 页：完整内联 HTML（tokens + groundback + 返回按钮），`noindex`，不设 cookie
- 尾部斜杠 301 重定向在各 Worker 内部处理

## Decision

选择 catch-all + service binding 而非 Cloudflare Pages Routes 的原因：每个 Worker 独立部署、独立回滚，互不影响。
